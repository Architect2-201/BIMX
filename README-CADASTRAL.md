# NAPR & maps.gov.ge Cadastral Integration Guide (საჯარო რეესტრი)

ეს დოკუმენტი აღწერს **BIMX Studio**-ს მიწის ნაკვეთის AI ანალიზის მოდულში **maps.gov.ge (NAPR — საჯარო რეესტრის ეროვნული სააგენტო)** ინტეგრაციას, უსაფრთხოების/კონფიდენციალურობის პრინციპებს და შემდგომი გაფართოების ნაბიჯებს.

---

## 1. ძირითადი პრინციპი: მონაცემთა დაცვა და „კოდი არ ინახება“

- **In-Memory / Client-Side Processing**: მომხმარებლის მიერ შეყვანილი საკადასტრო კოდი მუშავდება მხოლოდ ბრაუზერის მეხსიერებაში (React State / Vanilla JS runtime).
- **არავითარი ლოგირება ან შენახვა**: არც frontend და არც Node.js / Next.js backend არ ინახავს შეყვანილ საკადასტრო კოდებს დისკზე, ბაზაში ან ლოგ-ფაილებში.
- **პირდაპირი უსაფრთხო ძებნა**: ძებნა ხორციელდება უშუალოდ მომხმარებლის ბრაუზერიდან ოფიციალურ პორტალზე: `https://maps.gov.ge/map/portal`.

---

## 2. საკადასტრო კოდის ფორმატის ვალიდაცია

ქართული საკადასტრო კოდის სტანდარტული ფორმატი შედგება წერტილებით ან ტირეებით გამოყოფილი სექციებისგან:
- ფორმატი: `XX.XX.XX.XXX.XXX` ან `XX-XX-XX-XXX-XXX` (სადაც ბოლო სექციები შეიძლება იყოს 2 ან 3 ციფრიანი, მაგ. `01.15.02.038.003` ან `01.10.09.001.001`).
- რეგულარული გამოსახულება (Regex):
  ```typescript
  const CADASTRAL_CODE_REGEX = /^\d{2}[.\-]\d{2}[.\-]\d{2}[.\-]\d{2,3}[.\-]\d{2,3}$/;
  ```
- ნორმალიზაცია:
  ```typescript
  function normalizeCode(raw: string): string {
    return raw.trim().replace(/\s+/g, "");
  }
  ```

## 3. რატომ Safe Client-Side Embed & External Tab მიდგომა?

`maps.gov.ge`-ს არ გააჩნია საჯაროდ დოკუმენტირებული და ღია REST API გარე დეველოპერებისთვის.
ამიტომ სისტემა იყენებს **სანდო (Safe) მიდგომას**:
1. **ინტეგრირებული Iframe ჩვენება**: მომხმარებელი ხედავს ოფიციალურ რუკას პირდაპირ BIMX პლატფორმის „maps.gov.ge პორტალი“ ჩანართში.
2. **პირდაპირი გახსნის ღილაკი („გახსენი ცალკე ტაბში ↗“)**: ზოგიერთი სამთავრობო პორტალი უსაფრთხოების მიზნით ზღუდავს iframe-ში ჩატვირთვას (`X-Frame-Options: SAMEORIGIN` ან CSP ჰედერებით). ასეთ შემთხვევაში, მომხმარებელს ერთი კლიკით შეუძლია გახსნას ოფიციალური პორტალი ახალ ტაბში.
3. **ინსტრუქცია**: მითითებულია საკადასტრო კოდი, რომლის კოპირებაც მომხმარებელს შეუძლია საძიებო ველში.

## 4. რეალური NAPR Endpoint-ის დადგენა (DevTools ინსტრუქცია)

თუ სამომავლოდ გსურთ ნაკვეთის კონტურის (პოლიგონის კოორდინატების) და ფართობის პირდაპირი პროგრამული წაკითხვა ArcGIS-ის სერვისიდან 3D სცენის ავტომატური კვებისთვის:

1. გახსენით ბრაუზერში: `https://maps.gov.ge/map/portal`
2. გახსენით Developer Tools (`F12` ან `Ctrl+Shift+I`) და გადადით **Network** ტაბზე.
3. აირჩიეთ ფილტრი: **Fetch/XHR**.
4. საიტის საძიებო ველში ჩაწერეთ საკადასტრო კოდი (მაგ. `01.15.02.038.003`) და დააჭირეთ ძებნას.
5. Network ჩამონათვალში მოძებნეთ request, რომელიც აბრუნებს ნაკვეთის გეომეტრიას (ჩვეულებრივ ეს არის ArcGIS Server-ის `MapServer/<layerId>/query` ან `identify` მოთხოვნა).
6. შეამოწმეთ Response JSON — შეიცავს თუ არა `features[0].geometry.rings` ან GeoJSON კოორდინატებს.
7. დააკოპირეთ URL და ჩასვით `server.js`-ში ან `app/api/parcel/route.ts`-ში:
   ```typescript
   const upstreamUrl = `https://<NAPR_ARCGIS_SERVER>/arcgis/rest/services/.../MapServer/0/query?where=CADASTRAL_CODE='${cadastralCode}'&outFields=*&f=geojson`;
   ```

## 5. Stateless Proxy (`server.js` & `app/api/parcel/route.ts`)

თუ საჯარო რეესტრის სერვერი არ აბრუნებს CORS ჰედერებს (`Access-Control-Allow-Origin: *`), ბრაუზერიდან პირდაპირი `fetch()` დაიბლოკება.
ამისთვის სისტემაში მოცემულია **Stateless Proxy**:
- Node.js: `GET /api/parcel?code=01.15.02.038.003`
- Next.js: `app/api/parcel/route.ts`
- **წესი**: პროქსი მხოლოდ გადაამისამართებს მოთხოვნას upstream სერვერზე და აბრუნებს პასუხს; მონაცემი მეხსიერებიდან მაშინვე იშლება მოთხოვნის დასრულებისთანავე.
